# 📜 دستور التطوير البرمجي لمشروع رقيم (.specify/memory/constitution.md)

## 📌 المبادئ الحاكمة الأساسية (Core Articles)

### المادة 1: الهوية الأوفلاين المطلقة (Zero-Network Architecture)
1. تطبيق **رقيم (Raqeem)** يعمل بنسبة **100% محلياً ودون أي اتصال بالإنترنت**. وضع الطيران (Airplane Mode) هو بيئة العمل الطبيعية والأساسية للتطبيق.
2. يُحظر حظراً تاماً تضمين أي صلاحيات اتصال (`INTERNET` أو `ACCESS_NETWORK_STATE`) في `AndroidManifest.xml`.
3. يُمنع منعاً باتاً استدعاء أي خدمة سحابية خارجية (Google Speech, Gemini, OpenAI, إلخ) أو تنزيل ملفات أو نماذج من الشبكة أثناء تشغيل التطبيق.

### المادة 2: محرك تحويل الصوت إلى نص (Whisper On-Device STT)
1. المحرك الصوتي الوحيد المعتمد هو **whisper.cpp** بنماذج GGML المخزنة محلياً على الجهاز.
2. يُحظر كلياً استخدام واجهات `android.speech.SpeechRecognizer` أو `RecognizerIntent` أو استدعاء حوارات Google.
3. التقاط الصوت يتم حصراً عبر `AudioRecord` الخام بتنسيق 16kHz Mono 16-bit PCM، وتُفرغ العينات مباشرة في محرك Whisper عبر JNI.
4. حساب السعة (Amplitude) يتم رياضياً من عينات PCM (RMS) دون أي مكتبات خارجية.

### المادة 3: منهجية دورة حياة التطوير الموجه بالمواصفات (Spec-Kit SDLC)
1. تسلسل العمل إلزامي وغير قابل للتجاوز:
   `AGENTS.md ➔ intent.md ➔ spec.md ➔ plan.md ➔ tests (Red) ➔ code (Green) ➔ review & refactor`.
2. **يُمنع كتابة أي سطر كود برمجي تطبيقي قبل كتابة وتحديث وثائق intent وspec وplan وكتابة الاختبارات الفاشلة أولاً (TDD).**
3. الصدق التام في تقارير المراجعة (`review.md`): لا يُدّعى أي إنجاز إلا بناءً على مخرجات أوامر فعلية تم تشغيلها، وما يتطلب جهازاً حقيقياً يُذكر صراحةً أنه يحتاج اختباراً يدوياً.

### المادة 4: نقاء الكود وحظر المحاكاة الزائفة
1. وحدة `shared/src/commonMain` تبقى نقية (Pure Kotlin) بدون أي تسريب لواجهات أندرويد إلا عبر `expect/actual`.
2. يُحظر كود المحاكاة الوهمي (كاستخدام `delay()` ومحاكاة الاستجابات أو إرجاع نصوص ثابتة) خارج مجلدات الاختبار (`commonTest`).
3. يُحظر تحليل الأخطاء الهش بالنصوص مثل `String.contains("5")` أو استخدام الـ Reflection بين الوحدات.
