# 📜 دستور التطوير البرمجي لمشروع رقيم (.specify/memory/constitution.md)

## 📌 المبادئ الحاكمة الأساسية (Core Articles)

### المادة 1: الهوية الأوفلاين المطلقة (Zero-Network Architecture)
1. تطبيق **رقيم (Raqeem)** يعمل بنسبة **100% محلياً ودون أي اتصال بالإنترنت**. وضع الطيران (Airplane Mode) هو بيئة العمل الطبيعية والأساسية للتطبيق.
2. يُحظر حظراً تاماً تضمين أي صلاحيات اتصال (`INTERNET` أو `ACCESS_NETWORK_STATE`) في `AndroidManifest.xml`.
3. يُمنع منعاً باتاً استدعاء أي خدمة سحابية خارجية (Google Speech, Gemini, OpenAI, إلخ) أو تنزيل ملفات أو نماذج من الشبكة أثناء تشغيل التطبيق.

### المادة 2: محرك تحويل الصوت إلى نص (Whisper On-Device STT)
1. المحرك الصوتي الوحيد المعتمد هو **whisper.cpp** بنماذج GGML المخزنة محلياً على الجهاز.
2. يُحظر كلياً استخدام واجهات `android.speech.SpeechRecognizer` أو `RecognizerIntent` أو استدعاء حوارات Google أو أي ذكر لها في الكود والتعليقات.
3. التقاط الصوت يتم حصراً عبر `AudioRecord` الخام بتنسيق 16kHz Mono 16-bit PCM، وتُفرغ العينات مباشرة في محرك Whisper عبر JNI.
4. حساب السعة (Amplitude) يتم رياضياً من عينات PCM (RMS) دون أي مكتبات خارجية.

### المادة 3: منهجية دورة حياة التطوير وسياسة الاختبارات (التعديل الدستوري v3)
1. تسلسل العمل إلزامي وغير قابل للتجاوز:
   `AGENTS.md ➔ intent.md ➔ spec.md ➔ plan.md ➔ tests ➔ code ➔ review & refactor`.
2. **سياسة الاختبارات المعتمدة:**
   - **اختبارات آلية صارمة** للمنطق المالي المحاسبي، معالجة النصوص واللهجات العربية، وسلامة التخزين والترحيل (Unit Tests في `commonTest`).
   - **فحص يدوي على أجهزة حقيقية** لطبقة واجهات المستخدم والأنيميشن والانتقالات، مع تجنب تضييع الجهد في اختبارات UI آلية هشة.
3. **حظر المحاكاة والتأخير الزائف:** يُمنع تماماً استخدام `delay()` أو أي استجابات محاكاة وهمية داخل كود الإنتاج.
4. **الصدق التام في تقارير المراجعة:** لا يُدّعى أي إنجاز إلا بناءً على أدلة فعلية ومخرجات أوامر موثقة، وما يتطلب جهازاً حقيقياً يُصنف صراحةً كفحص يدوي مطلوب.

### المادة 4: نقاء الكود والتصميم المعماري
1. وحدة `shared/src/commonMain` تبقى نقية (Pure Kotlin) بدون أي تسريب لواجهات أندرويد إلا عبر عقود `expect/actual`.
2. هيكلية MVI أحادية الاتجاه (Unidirectional Data Flow) مع فصل كامل بين الحالة (UiState)، الأحداث (Intent)، والآثار الجانبية (Effect).
3. معالجة الأخطاء قطعية ومحكمة، ولا يُسمح بالتحليل الهش للنصوص أو الاعتماد على Reflection.

### المادة 5: المحاسبة المالية ودفتر المستحقات (Financial Accounting Ledger)
1. **حصص الآخرين ديون ملزمة:** أي مبلغ يدفعه المستخدم نيابة عن طرف آخر يُسجل كمستحق تحصيل (Receivable) حتى يتم تسويته، ولا يُحسب في مصاريف المستخدم الشخصية.
2. **المبلغ الفعلي للمستخدم:** `effectiveAmount = myShare ?: amount`. جميع العمليات التجميعية والتقارير والميزانية والرادار تعتمد حصرياً على `effectiveAmount`.
3. **دفتر الأستاذ الموحد:** يُعد `ReceivablesLedger` المصدر الوحيد للحقيقة (Single Source of Truth) لجميع حسابات وأرصدة وأعمار الديون.
4. **حظر الحذف الصامت:**
   - التسديدات لا تُحذف؛ بل تُلغى محاسبياً بحالة `voided` مع توثيق السبب والتاريخ.
   - المصاريف المرتبطة بتخصيصات تُحذف حذفاً ناعماً (`deletedAt`) وتبقى في سجل التدقيق المالي.
5. **النزاهة والتدقيق:**
   - توليد أرقام مرجعية تسلسلية وحيدة (`refNo`) لكل قيد مالي وتخصيص وتسديد.
   - فصل تاريخ السداد الفعلي (`settledAt`) عن وقت تسجيل العملية (`recordedAt`).
   - دعم سجل التدقيق الكامل (`audit_log`) وفحوصات المطابقة الرياضية المتوازنة.
   - حظر الجمع بين العملات المختلفة قطعياً.

### المادة 6: التخزين الذري والتوافق الخلفي المستدام
1. **حماية التوافق الخلفي:** يُحظر تعديل أو حذف أسماء الحقول القائمة في نماذج البيانات (`ExpenseItem`، `ExpenseSplit`) لضمان عدم تلف بيانات المستخدمين السابقة.
2. **الكتابة الذرية (Atomic File I/O):** تُكتب البيانات أولاً إلى ملف مؤقت (`.tmp`) ولا تُعتمد إلا بعد نجاح الكتابة عبر استبدال ذري للملف الأصلي لمنع التلف عند انقطاع الطاقة.
3. **الحماية من التلف:** عند مواجهة ملف JSON تالف، يُعاد تسميته إلى `.corrupt` مع ختم زمني للإنقاذ والتحليل بدلاً من مسحه والكتابة فوقه.

### المادة 7: هوية التصميم وتجربة المستخدم (UnSlop UX Standard)
1. **لوحة الألوان المعتمدة (Fintech Slate & Emerald):**
   - خلفية النظام: `BackgroundSlate #0E131F`
   - بطاقات وأسطح: `SurfaceCard #182032`
   - اللون اللامع الأساسي الوحيد: `EmeraldGreen #00C48C`
   - اللمسة الثانوية: `ElectricCyan #22D3EE`
   - التنبيه والمصروف: `CoralRose #FF5C5C`
2. **شعرية الحدود والشبكة:** حدود نحيفة 1dp بشفافية 8%، شبكة تصميمية تعتمد مضاعفات 4px، وأنصاف أقطار زوايا متداخلة ومتناسقة.
3. **صفر إيموجي ورموز نصية:** يُمنع منعاً باتاً استخدام الإيموجي أو الرموز النصية التعبيرية في أي واجهة، وتُستبدل بأيقونات `RaqeemIcons` المتجهة.
4. **اللغة والاتجاه:** خط Cairo عبر جميع عناصر الواجهة، مع دعم كامل للاتجاه من اليمين إلى اليسار (RTL Immersion) ونصوص هادئة خالية من علامات التعجب والابتذال.
